## Categories

For this catalog, an agent development environment is a product that gives a person a persistent place to direct coding agents, inspect their work and move changes toward delivery. Multi-agent support is something to research, not a prerequisite that would exclude useful substitutes.

| Category | Inclusion rule |
| --- | --- |
| A. Agent workspaces and orchestration | The main workflow is directing and reviewing agent work across sessions, tasks or workers. Includes local, remote and managed-cloud products. |
| B. Coding environments and agents | Editors, coding agents and software-engineering services that can substitute for part or all of that workflow. Product surfaces stay explicit. |
| C. Application builders | Prompt-to-application products that compete for the outcome of building software, often with their own hosting and deployment workflow. |
| D. Components and broader work tools | Agent runtimes, remote companions, orchestration reference projects, execution infrastructure and general work agents. Useful context for the catalog, but not automatically equivalent ADE alternatives. |

Each product gets one primary category based on its observed main workflow. These assignments are analyst judgments, not vendor labels. Local or cloud, open source or closed, single-user or team, and model-provider independence are separate attributes under the [rubric](comparison-framework.md). "Watch" and "retired" are research states, not product categories.

## Decision rules and evidence

Categories follow the [A-D definitions](#categories) above. A runnable product that directs, coordinates or reviews coding agents against the user's repository is A or B. Prompt-to-application builders are C. SDKs, protocols, skill packs, execution infrastructure, explicitly described reference implementations and general personal or business assistants remain D. Existing coding agents inside a general assistant do not by themselves change its main workflow. Repository bots with a directly usable coding or review workflow are B; a sample implementation of such a bot remains D.

Each ledger row has a description, a disposition, a short exact first-party quotation, a source link and a maintenance finding. Quoted text preserves vendor wording, with markup removed and whitespace normalized. Some owners describe their product in a heading rather than a grammatical sentence. Five unavailable locations have no quotable product sentence: `kadro-ade`, `agentsmesh`, `better-agent`, `dex` and `factory-owainlewis`. Their exact HTTP reason, "Not Found", is recorded instead. This is an access result, not an invented vendor statement. Ariana's surviving first-party guide supplies a scope quotation despite its registered repository returning 404.

Maintenance uses the latest default-branch commit and latest returned GitHub release, or dated first-party release notes. "Yes" means dated public maintenance activity within the six-month window, not a guarantee of support or a hands-on result. A page loading, a footer year or a repository push to another branch does not establish maintenance. "Unknown" records the evidence gap. All URLs and counts were retrieved on **2026-11-08**. GitHub sources were opened through the authenticated read-only API and their README files; dates and star counts came from repository, latest-commit and release responses. Vendor pages were treated as data throughout.

The six-month screening rule uses the cutoff **2026-05-08**: an archived repository, unavailable registered project, last release older than six months, or no release plus no public default-branch work in six months triggers the flag. The flag is a dated screening signal, not a finding that a project has ended. A stale release can coexist with a recent commit. **Eleven** flagged projects still have recent public code activity; six of them are ADEs: Aperant, Automaker, ClawTeam, run-gemini-cli, tutti and VibeCraft. Their ledger rows are labelled active. Aperant explicitly says its 3.0 rebuild continues elsewhere and its 2.x app is in maintenance mode.

404s establish that the checked public location is unavailable. They do not distinguish deletion, private relocation or company shutdown. Current first-party offerings take precedence over an old source location: Daytona remains adjacent because its archived repository says core development moved private while the current site still offers sandbox infrastructure. JAT has an unavailable historical repository but a live current product site, install path and IDE documentation; its maintenance remains unknown.
